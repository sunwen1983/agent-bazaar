# Deployment prep — Agent Bazaar (M1)

Nothing here is deployed yet. This is the checklist and the exact
commands for deploy day. Two different keys are involved — do not
confuse them (see "Keys" below).

## What gets deployed

| Piece | Host | Source | Public URL |
|-------|------|--------|------------|
| Origin A: concierge site | Cloudflare Pages project `agent-bazaar` | `public/origin-a` | https://agent-bazaar.pages.dev |
| Origin B: flights site | Cloudflare Pages project `agent-bazaar-flights` | `public/origin-b` | https://agent-bazaar-flights.pages.dev |
| Origin C: stays + guide site | Cloudflare Pages project `agent-bazaar-stays` | `public/origin-c` | https://agent-bazaar-stays.pages.dev |
| mcpgate + 3 mock backends | fly.io app `agent-bazaar-mcpgate` | `mcpgate/` (Dockerfile + fly.toml) | https://agent-bazaar-mcpgate.fly.dev |

The three origin URLs are already baked into the static bundles
(`links.json`, manifests, `--site-url` at build time) — **do not
rename the Pages projects**, or rebuild with `scripts/build-bundles.sh`
after renaming. The bundles already contain `_headers` with
`Access-Control-Allow-Origin: *` on the manifest/network/links files;
Pages serves them as-is, no build step, no Functions needed.

## Keys — two different ones

### Key A — mcpgate demo API key (gateway auth)

- **What**: the `X-API-Key` browsers send to `POST /mcp/{backend}`.
- **Generated by Wen at deploy time**: `openssl rand -hex 16`.
- **Where it goes**: (1) fly secret — `fly secrets set DEMO_API_KEY=<key>`
  (the container entrypoint injects it into the gateway config);
  (2) the bazaar site's frontend config (M2 UI work) so the browser
  sends it — **public by design** (rate-limited to 30 req/min, backends
  are read-only mock data). Rotate it after the contest; rotating means
  updating both places.
- **Never** reuse a key from any other service for this.

### Key B — DeepSeek demo LLM key (model calls)

- **What**: funds the default model path in the demo (see
  `docs/demo-key.md`, decision D4-b).
- **Created by Wen at deploy time**: a **separate DeepSeek account/key
  for the demo only**, topped up with a small prepaid balance (**~$5
  cap**). Never a production key, never an account with auto-recharge.
- **Where it goes**: seeded into the visitor's browser localStorage by
  the site's `site.js` (M2 work) — **never committed to the repo**.
  The demo video uses Wen's own key via BYOK (typed off-camera).
- **Fallback**: if Wen decides against any key exposure, delete the
  seeding code and the site is pure BYOK (worse judge experience).

## Deploy order (independent pieces; either order works)

### 1. Cloudflare Pages (3 projects)

Option 1 — dashboard direct upload (simplest, no CLI):
`Cloudflare dashboard → Workers & Pages → Create → Pages → Direct Uploads`,
project name `agent-bazaar` / `agent-bazaar-flights` /
`agent-bazaar-stays`, upload the matching `public/origin-*` folder.

Option 2 — wrangler (repeatable):

```bash
npx wrangler pages deploy public/origin-a --project-name agent-bazaar
npx wrangler pages deploy public/origin-b --project-name agent-bazaar-flights
npx wrangler pages deploy public/origin-c --project-name agent-bazaar-stays
```

Option 3 — Git integration (auto-deploy on push): connect the
`sunwen1983/agent-bazaar` repo, one Pages project per origin, build
command empty, output directory `public/origin-a` (etc.). Best for
later iterations; not required for the first deploy.

Verify each site serves its manifest with the CORS header:

```bash
curl -s -D - -o /dev/null https://agent-bazaar.pages.dev/agent-manifest.json \
  | grep -i "access-control-allow-origin"
# expect: Access-Control-Allow-Origin: *
```

### 2. fly.io mcpgate

```bash
cd mcpgate
fly launch --no-deploy   # first time only; confirm app name agent-bazaar-mcpgate, region dfw
fly secrets set DEMO_API_KEY="$(openssl rand -hex 16)"   # Key A — save the value for the site config (M2)
fly deploy               # remote builder; no local Docker needed
curl https://agent-bazaar-mcpgate.fly.dev/healthz   # expect 200
curl -s -X POST https://agent-bazaar-mcpgate.fly.dev/mcp/flights \
  -H 'Content-Type: application/json' -H "X-API-Key: <Key A>" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'   # expect search_flights listed
```

If `fly launch` asks about Postgres/Redis: no to both (not needed).
Cost note: one shared-cpu-1x 256 MB machine, always on
(`auto_stop_machines = "off"` in `fly.toml`) so judges never hit a
cold start. Check the current free allowance before deploying; if it
changed, this is a few dollars a month at most.

## After both are up

1. Re-run the `mcpgate/LOCAL_E2E.md` checks against the public
   `https://agent-bazaar-mcpgate.fly.dev` URL (same curls, different host).
2. Browser check (Mila): open https://agent-bazaar.pages.dev in a real
   browser, run the one-sentence demo, verify the consent popup, the
   cross-origin peer load, and the MCP calls in the trace. This is the
   check the VM could not do locally — it is the first thing to do
   once the public URLs exist.
3. Only then is M1 done and M2 (marketplace UI: card wall, verification
   panel, trace, BYOK demo-key seeding) unblocked.
